## 1. ПРОДУКТ

### 1.1 Одним абзацем
Brandpilot — SaaS, который по URL сайта компании за ≤ 90 секунд строит профиль бренда (Brand DNA: палитра, шрифты, tone of voice, архетип, ЦА, УТП), генерирует контент-план из 50+ идей, создаёт посты с фирменным визуалом, публикует их по расписанию в соцсети и обучается на решениях пользователя (одобрил/отклонил). Целевой пользователь — малый бизнес без маркетолога. Обещание: «Вставил URL → одобрил → всё публикуется само».

### 1.2 Ключевые дифференциаторы (защищать в каждом решении)
1. Brand DNA с извлечением визуальной идентичности из сайта + self-check на галлюцинации.
2. Послойная библиотека шаблонов визуала + Designer — визуал реально в цветах/шрифтах клиента.
3. Feedback loop: каждое действие пользователя (`feedback_events`) влияет на следующую генерацию.
4. Превью 6 постов до регистрации и до оплаты.
5. «Сделано в ЕС, данные в ЕС» — GDPR как продуктовый аргумент.

### 1.3 Персоны
| Персона | Ключевой сценарий |
|---|---|
| Владелец строительной фирмы, нет маркетолога | URL → одобрил 30 постов → забыл на месяц |
| Админ стоматологии | Визуал в фирменных цветах; страх медицинских ошибок в тексте |
| Управляющая бутик-отелем | Один пост → адаптации под IG/FB/LinkedIn |
| CMO-одиночка в SaaS | LinkedIn-экспертность, карусели |
| Маркетолог e-commerce | Много товаров, акции, Meta Ads (фаза 2) |
| Агентство (фаза 2) | Мультибренд, white-label |

## 4. ФИКСИРОВАННЫЕ РЕШЕНИЯ (ADR summary)
- ADR-01: NestJS, не FastAPI, для основного API — единый TS-стек фронт/бэк/воркеры.
- ADR-02: OpenAPI генерируется из NestJS-декораторов; фронт использует только сгенерированный клиент `packages/api-client`. Ручные fetch к API запрещены.
- ADR-03: Единая JSON-схема `DesignDoc` для Designer и render-svc (раздел 9). Любое изменение — через `packages/shared` + миграция шаблонов.
- ADR-04: Все AI-вызовы только через `packages/ai`. Прямые вызовы SDK провайдеров вне пакета запрещены.
- ADR-05: Промпты — файлы в `prompts/` с версией; изменение промпта требует прогона `pnpm eval` и приложенного отчёта.
- ADR-06: Multi-tenancy через RLS (`SET app.workspace_id`) + явный `workspace_id` в каждом запросе Prisma. Оба уровня обязательны.
- ADR-07: Публикация — at-least-once с идемпотентностью по `publish_jobs.idempotency_key = post_variant_id + attempt_group`.
- ADR-08: Инфраструктурная схема AI — «только API» на старте; `packages/ai` проектируется так, чтобы любой тир можно было перевести на self-hosted vLLM-эндпоинт заменой конфига.
- ADR-09: Персональные данные (email, телефон) не передаются в промпты LLM и не пишутся в логи. Краул-контент перед LLM проходит PII-скраббер.
- ADR-10: Мягкое удаление везде (`deleted_at`), hard-delete — отдельный cleanup-воркер через 30 дней.

## 5. КОНВЕНЦИИ

### 5.1 Код
- TypeScript strict, ESLint + Prettier (конфиг в репо), no `any` без `// eslint-disable` с причиной.
- Именование: файлы `kebab-case.ts`, классы `PascalCase`, БД `snake_case`, enum-значения `snake_case` строки.
- Ошибки API: RFC 7807 `{ type, title, status, detail, instance, code }`; коды в `packages/shared/errors.ts`.
- Деньги — integer cents; время — UTC ISO в API, `timestamptz` в БД; TZ workspace применяется только на UI/в scheduler.
- Логи — structured JSON (pino), поля `workspace_id`, `user_id`, `trace_id`, никаких PII.
- Фичефлаги: `packages/shared/flags.ts` + env `FEATURE_*`. Все Phase-2 модули — за флагом.

### 5.2 Git
- Ветки `feat/E4.3-template-library`, `fix/...`, `chore/...`. Conventional commits.
- PR template: Task ID · Summary · How to test · Screenshots (UI) · Eval report (prompts) · Concerns.
- CI обязательные проверки: lint, typecheck, unit, integration (testcontainers), e2e smoke, prisma migrate diff, OpenAPI diff (breaking → fail).

### 5.3 Тесты
- Unit: Vitest (web, packages), Jest (api). Покрытие бизнес-логики ≥ 80% в `packages/ai`, `apps/api/src/{publish,billing,brand}`.
- Integration: Postgres + Redis через testcontainers; адаптеры платформ — через `nock`/MSW с записанными фикстурами.
- E2E: Playwright по UC из раздела 11; AI-вызовы в e2e мокаются детерминированными фикстурами (`packages/ai` имеет `MockProvider`).
