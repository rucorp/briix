## Что сделано

### 1. Скачок левой колонки при работе демо — устранён

- `assets/css/main.css:499` — `.hero-grid`: `align-items: center` → **`align-items: start`**. Левая колонка стоит у верха строки; рост `.demo-card` больше не центрирует и не сдвигает её.
- `.hero-copy` (новый класс, `index.html` и `en/index.html`) — **залипание чистым CSS**, ровно по сниппету из задания:
  ```css
  @media (min-width: 1081px) {
    .hero-copy { position: sticky; top: calc(var(--header-h) + 28px); align-self: start; }
  }
  ```
  `--header-h` = 72px — токен, не хардкод. Брейкпоинт симметричен существующему `@media (max-width: 1080px)`, где `.hero-grid` схлопывается в одну колонку. JS не трогал.

### 2. `overflow: hidden` на `.hero` и свечение

`overflow: hidden` убран — он делал `.hero` скролл-контейнером и глушил sticky. Свечение сохранено **пиксель-в-пиксель**: геометрия `.hero::before` (`inset: -220px -10% auto`, те же градиенты) не менялась, добавлен только `clip-path: inset(220px 8.3333% 0 8.3333%)` — 8.3333% от ширины псевдо-элемента (=120% секции) = ровно 10% секции с каждой стороны, то есть обрезка ровно по границе hero, как раньше. Clip-path не создаёт скролл-контейнер и не трогает sticky. Горизонтального скролла нет (клип по границам секции).

### 3. Скачок высоты демо-карты

- `min-height: 430px` на `.demo-card` — короткие состояния (idle и генерация) не «дышат» друг относительно друга: на всём протяжении генерации карточка не двигается.
- Рост к результату смягчён анимацией раскрытия (`@keyframes demo-grow` по `max-height`, `0.55s ease`) внутри **`@media (prefers-reduced-motion: no-preference)`** — блок создан (в CSS его не было). Плавная интерполяция `height: auto` в чистом CSS невозможна (переход вычисляемой высоты не анимируется без JS) — выбрано разрешённое заданием «разрешить анимацию перехода».
- При `prefers-reduced-motion: reduce` — мгновенное состояние, без анимации.

### 4. Заголовок: ≤3 строк на 1440px

Измерено реальным шрифтом (Manrope Variable, weight 800, letter-spacing −0.032em, fontTools):

| Строка | 50px | 52px | 56px |
|---|---|---|---|
| «Вставьте адрес сайта —» | 549px | 571px | 615px |
| «получите месяц контента» | **618px** | **642px** | **692px** |
| «в фирменном стиле» | 469px | 487px | 525px |

Ограничивающая — вторая строка: при `left ≈ 541px` она не влезает даже на 48px. Числа задания (56–60px) дают 4–5 строк при любой реалистичной ширине колонки. Решение:

- `.hero-grid`: колонки `1.05fr/1fr` → **`1.5fr/1fr`** (при контейнере 1112px: left = 634px, right = 422px);
- `.hero h1`: `clamp(42px, 5.8vw, 68px)` → **`clamp(42px, 4.3vw, 50px)`** + **`text-wrap: balance`**.

Проверено по метрикам во всём диапазоне двухколоночной вёрстки:

| Вьюпорт | Шрифт | Левая колонка | Самая широкая строка | Запас |
|---|---|---|---|---|
| 1440 / 1280 | 50px | 634px | 618px | +16px |
| 1163–1208 | 50px | 625–634px | 618px | +7…16px |
| 1100 | 47.3px | 598px | 584px | +13px |

RU при 1440: ровно **3 строки** — «Вставьте адрес сайта —» / «получите месяц контента» / «в фирменном стиле» (переносы по `<br>` и по смысловым кускам; вторая половина не влезает в один ряд ни при каком разбиении, так что разбиение детерминированное). Текст не изменён (в т.ч. по смыслу).

### 5. Английская версия — логика переносов

Та же разметка (`<br>`), тот же CSS, та же колонка. При 1440 EN тоже **3 строки**: «Enter your website URL —» / «get a month of content» / «in your brand style» (455px + 400px укладываются в 634px с большим запасом; счётчик строк RU = EN). При узких вьюпортах обе фразы балансируются `text-wrap: balance` одинаково. Смысл текста не изменён.

## Как проверял скачок при работе демо

1. Статически: при `align-items: start` + sticky верх левой колонки привязан к верху строки грида — высота правой колонки не влияет на позицию левой ни при каком состоянии демо (idle/генерация/результат).
2. Метрики роста состояний: idle и генерация удерживаются общим `min-height: 430px` (переход idle↔генерация — без движения); рост к результату идёт только вниз и сглажен анимацией раскрытия.
3. Высота элементов над вьюпортом при демо не меняется — страница не дёргается при скролле.

## Что осталось непроверенным

- **Визуальная проверка в реальном браузере не выполнялась** — браузера в песочнице нет. Всё проверено статически: парсинг CSS (tinycss2), метрики шрифта (fontTools по реальным woff2), расчёт вёрстки по вьюпортам 1440/1280/1163/1100/1081/1024/768/390. Рекомендую прогнать чек-лист глазами на живом сайте, особенно: ощущение анимации роста демо-карты и точность обрезки свечения.
- Анимация роста демо-карты проверена только расчётом (`max-height`-раскрытие); фактическое ощущение плавности и длительность стоит оценить в браузере.
- Совместимость `text-wrap: balance` со старыми браузерами: без поддержки строка просто переносится жадно — хуже не становится, но число строк может отличаться в старом Safari/Firefox.
