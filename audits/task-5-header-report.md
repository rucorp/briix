## 1. Бургер за правым краем — те самые 29px

### Что было сломано

`.header-inner` — flex-строка с `gap: 24px`, без переноса. Порядок и режимы сжатия:

| Элемент | CSS | Сжимается? |
|---|---|---|
| `.logo` | `flex: none` | нет |
| `.nav` | `display: none` при ≤1279px | — |
| `.header-cta` | `margin-left: auto; flex: none` | нет |
| `.burger` | `width: 44px`, `flex-shrink` по умолчанию = 1 | **да, единственный в строке** |

`.header-cta` с `flex: none` резервирует всю свою max-content ширину и стоит **перед**
бургером. Свободного места в строке не хватает, и браузер сжимает ровно один элемент —
бургер: с `44px` до его `min-content`.

`min-content` бургера = **32px**: `<span>` шириной 20px плюс `padding-inline: 6px + 6px`,
которые `<button>` получает из UA-таблицы стилей (сброс в `main.css` обнуляет `border`,
но не `padding`). Дальше сжиматься некуда (`min-width: auto`), и остаток недостачи
выталкивает кнопку за правый край.

### Расчёт сходится с замером из браузера до 0.3px

Модель (`audits/task-5-header-metrics.py`), состояние «до правки», вьюпорт **470px**, RU:

```
контейнер      min(470, 1160) − 48            = 422.00 доступно
.logo          34 + 11 + «BRIIX» 50.84        =  95.84
gap                                     24.00
.header-cta    кнопка 192.41 + 10 + язык 44.50 + 10 + тема 42
                                              = 298.91   (btn-ghost скрыта при ≤1279)
gap                                     24.00
.burger        сжат браузером 44 → 32         =  32.00
                                              ---------
содержимое                                    = 474.70
правый край бургера   24 + 474.70             = 498.70  → scrollWidth = 499
переполнение          498.70 − 470            =  28.70  → «на 29px»
```

В тикете: документ **499px**, правый край бургера **ровно 499px**, выход за экран **29px**.
Модель даёт 498.70 / 498.70 / 28.70. Сходится она **только** при сжатом бургере: при
несжатом получилось бы 510.70. Так что заодно подтвердился не описанный в тикете дефект —
**кнопка была ещё и сплюснута на 12px** (44 → 32), иконка в ней стояла не по центру.

### Что исправлено

1. **`.burger { flex: none }`** — кнопка больше не участвует в сжатии и не уезжает.
2. **`@media (max-width: 600px) { .header-cta .btn { display: none } }`** — на узких
   экранах CTA-кнопки уходят из шапки в панель бургера (`.nav-cta`): влезть в шапку они
   не могут физически.

Расчёт порога (RU, худший случай):
`лого 95.84 + 24 + [кнопка 192.41 + 10 + язык 44.50 + 10 + тема 42 = 298.91] + 24 + бургер 44 = 486.75`,
плюс паддинги контейнера 48 → **535px**. Порог взят **600px**, а не 535px — запас на
расхождение метрик и рендеринга. EN-версии хватило бы 495px, так что порог один на обе.

Без кнопок шапка занимает `95.84 + 24 + 96.50 + 24 + 44 = 284.34` → помещается начиная
с **333px**; все вьюпорты из задания (от 360) в запасе.

### До / после

RU (модель, `doc` = ширина документа):

| Вьюпорт | ДО: doc | ДО: бургер | ПОСЛЕ: doc | ПОСЛЕ: бургер |
|---|---|---|---|---|
| 360 | 498.70 (+138.70) | 32px | **360.00** | 44px |
| 390 | 498.70 (+108.70) | 32px | **390.00** | 44px |
| 414 | 498.70 (+84.70) | 32px | **414.00** | 44px |
| **470** | **498.70 (+28.70)** | **32px** | **470.00** | **44px** |
| 600 | 600.00 | 44px | 600.00 | 44px |
| 601 | 601.00 | 44px | 601.00 | 44px |
| 768 / 1024 / 1080 / 1279 | без прокрутки | 44px | без прокрутки | 44px |
| 1280 / 1440 | без прокрутки | скрыт | без прокрутки | скрыт |

сжат до 32px); после правки прокрутки нет ни на одном вьюпорте.

ни в RU, ни в EN. Требование «документ на 470px равен 470px» выполнено.

## 2. Бургера нет на шести страницах

### Уточнение фактического состояния — оно отличается от тикета

Проверено по разметке всех 8 страниц:

| Страница | `.site-header` | `.nav` | `.burger` | Горизонтальная навигация |
|---|---|---|---|---|
| `index.html`, `en/index.html` | есть | есть | есть | есть на ≥1280px |
| `presentation.html`, `en/presentation.html` | **нет `<header>` вовсе** | нет | нет | нет ни на какой ширине |
| `investors/index.html`, `en/…` | нет (есть `.doc-header`) | нет | нет | нет ни на какой ширине |
| `fin-model/index.html`, `en/…` | нет (есть `.doc-header`) | нет | нет | нет ни на какой ширине |

Три поправки к постановке:

1. Брейкпоинт — **1279px, а не 760px**: `.nav { display: none }` и
   `.burger { display: inline-flex }` живут в `@media (max-width: 1279px)`.
2. На шести страницах навигация не «скрывается на мобильном» — **её там нет вообще**,
   ни на какой ширине. Скрываться нечему.
3. Про презентацию «с телефона некуда перейти» — неверно: `.deck-brand`
   (`position: fixed; top: 22px; left: 26px`) ссылается на `index.html` и видна на всех
   ширинах (при печати скрыты `.deck-controls`, `.deck-progress`, `.deck-hint`,
   `.deck-theme` — бренд не скрыт). Выход был, но единственный и не подписан как меню.

### Решение

**Один компонент бургера на все 8 страниц.** Логика вынесена в новый `assets/js/nav.js`,
который грузится на всех восьми страницах; из `landing.js` соответствующий блок удалён
(иначе на одной кнопке висело бы два обработчика).

`nav.js` не знает ничего о страницах: ему нужны `.burger` и `.nav`. К прежнему поведению
добавлены `Escape`, `aria-controls`, возврат фокуса на бургер и закрытие панели при
ресайзе, если бургер скрылся.

По страницам:

- **Лендинг (RU/EN)** — как было: горизонтальная `.nav` на ≥1280px, бургер ниже.
  В панель добавлены две CTA-кнопки (`.nav-cta`), чтобы на узких экранах действие не
  терялось вместе с кнопками из шапки.
- **Инвест-доки и финмодель (4 страницы)** — добавлена обычная `.site-header` с вариантом
  `menu-only`: логотип + бургер, горизонтальной навигации нет ни на какой ширине.
  В панели четыре перехода **с теми же подписями, что уже есть на этих страницах** в
  `.link-chip` («Продуктовый сайт», «Презентация проекта», «Раздел для инвесторов»,
  «Финансовая модель и калькулятор»), текущая страница помечена `aria-current="page"`.
- **Презентация (2 страницы)** — бургер добавлен в существующий кластер `.deck-theme`
  (рядом с языком и темой), 38×38px, в фирменном хроме слайдов. Панель та же, на весь
  экран. В `@media print` кластер скрыт целиком, так что в PDF бургер не попадает.

### Почему так

- **«Внутренние страницы без навигации» не годится.** Запрошенный результат — чтобы с
  телефона было куда перейти. Кроме того, до правки состояние было неодинаковым: на доках
  были чипы-ссылки и переключатели, на презентации — только бренд. Требование «одинаково
  на обеих языковых версиях» теперь выполнено буквально: разметка RU и EN отличается
  только текстами и префиксами путей.
- **Общий файл, а не дублирование.** Дублировать логику в `deck.js`, `finmodel.js` и ещё
  где-то для инвест-страницы (где своего скрипта, кроме `theme.js`, нет) — это четыре
  копии, которые разъедутся. Один файл на ~70 строк без зависимостей грузится везде;
  правило «статик без сборки и без CDN» не нарушено.
- **Почему на доках `menu-only`, а не полноценная горизонтальная навигация.** Эти страницы
  — непубличные документы с собственным тёмным `.doc-header` и рядом чипов. Добавлять туда
  второй ряд ссылок значило бы менять их десктопный вид, чего в задании нет. Бургер
  закрывает ровно запрошенную дыру и на десктопе ничего не ломает. Переключатели языка и
  темы намеренно **не** продублированы в новой шапке — они остались в `.doc-header`,
  второго набора нет (проверено тестом).
- **Почему бургер на презентации, а не «бренд и так есть».** Бургер даёт переходы на
  инвест-раздел и финмодель, которых с презентации не было вовсе, и делает выход
  одинаковым на всех страницах. Цена — одна кнопка 38px в уже существующем кластере.
- Ширина шапки `menu-only`: `95.84 + 24 + 44 = 163.84` + паддинги 48 = **211.84px** —
  помещается с 212px, то есть с большим запасом на любом телефоне.

## 3. Панель меню не перекрывала страницу

### Что было

```css
@media (max-width: 1279px) {
  .nav.open { position: absolute; top: var(--header-h); left: 0; right: 0; … }
}
```

Панель — полоса высотой по содержимому (~250px на пяти пунктах). Всё, что ниже её нижнего
края, оставалось видно: hero со своей липкой левой колонкой, и абзац `hero-sub` обрезался
ровно по границе панели.

**Поправка к формулировке тикета.** Фон панели был `var(--card)` — `#ffffff` в светлой теме
и `#1a1512` в тёмной, то есть **непрозрачный**. Сквозь сами пункты текст просвечивать не
мог. Речь именно о неполном покрытии: страница оставалась видна **под** панелью.

### Что сделано

Панель вынесена из медиа-запроса в базовые правила и стала полноэкранным перекрытием:

```css
.nav.open {
  position: absolute;
  top: var(--header-h); left: 0; right: 0;
  height: calc(100vh - var(--header-h));
  height: calc(100dvh - var(--header-h));
  background: var(--bg);
  overflow-y: auto; overscroll-behavior: contain;
  …
}
```

Почему `absolute` + явная высота, а не `position: fixed`: у `.site-header` есть
`backdrop-filter: blur(14px)`, а он (как `filter` и `transform`) делает элемент containing
block'ом для fixed-потомков. Панель считала бы вьюпортом саму шапку высотой 72px и
схлопнулась бы в ноль. `.site-header` — `sticky` с `top: 0`, её верх всегда совпадает с
верхом вьюпорта, поэтому `absolute` от шапки с высотой `100dvh − 72px` даёт ровно
полноэкранное перекрытие. `100vh` стоит первой строкой как откат для браузеров без `dvh`.

Прокрутку страницы при открытой панели не блокировал намеренно: панель непрозрачная и
занимает весь вьюпорт, страница под ней не видна, а `overscroll-behavior: contain` не даёт
скроллу проваливаться наружу. Так не появляется сдвиг вёрстки из-за исчезнувшего
скроллбара на десктопе.

На презентации панель позиционируется от вьюпорта (`position: fixed; inset: 0`) —
`.deck-theme` не имеет ни `backdrop-filter`, ни `transform`, там `fixed` работает как
обычно. `z-index` кластера поднят с 40 до 70, иначе `.deck-controls` (тоже 40, но позже в
DOM) рисовались бы поверх панели.

## 4. Две кнопки в шапке

### Было

```html
<a class="btn btn-ghost"   href="#demo">Смотреть демо</a>
<a class="btn btn-primary" href="#demo">Показать мои посты</a>
```

Один якорь, одна и та же прокрутка. На десктопе `.demo-card#demo` и так в hero — клик не
давал ничего.

### Стало

Тексты не менялись. Добавлен атрибут действия, логика — в `landing.js`:

```html
<a class="btn btn-ghost"   href="#demo" data-demo-action="watch">Смотреть демо</a>
<a class="btn btn-primary" href="#demo" data-demo-action="mine">Показать мои посты</a>
```

**«Смотреть демо» — показать готовое.** Всегда запускает встроенный демо-бренд
`nordhavn-studio.com`: посетитель видит полный результат (Brand DNA, 6 постов,
контент-план), ничего не вводя.

**«Показать мои посты» — показать своё.** Если в поле уже вписан домен — сразу генерирует
по нему. Если поле пустое — возвращает карточку на шаг ввода и ставит фокус в поле;
`:focus-within` даёт акцентный ореол, то есть отдельная подсказка не нужна.

Обе дополнительно прокручивают к карточке с отступом `высота шапки + 16px` — на телефоне
демо ниже первого экрана.

### Обоснование

- Кнопки теперь различаются **по результату, а не только по подписи**: одна отдаёт чужой
  готовый пример, вторая требует и обрабатывает ввод посетителя. Различие проверяемо без
  дизайна: после генерации по своему домену «Смотреть демо» возвращает демо-бренд — это
  отдельный assertion в тесте.
- «Смотреть демо» **всегда** что-то делает, в том числе на десктопе, где демо уже на
  экране: проигрывается анимация генерации. Это закрывает жалобу «выглядит как будто
  ничего не происходит». Альтернативу «если демо уже показано — только прокрутить» отверг:
  это ровно то поведение, на которое жаловались.
- «Показать мои посты» при пустом поле **не** подставляет демо-домен за посетителя:
  обещание кнопки — «мои посты», подстановка сделала бы её копией первой.
- `href="#demo"` сохранён на обеих кнопках — без JS они продолжают работать как якоря.
- Обработчик общего плавного скролла по `a[href^="#"]` пропускает `[data-demo-action]`,
  чтобы два обработчика не дрались за один клик.

**Попутно исправлен баг в том же коде.** Кнопка «Другой сайт» (`#demo-change`) скрывала
`#demo-gen` и `#demo-result`, но не показывала обратно `#demo-idle` — после завершения
генерации тело карточки оставалось пустым, поле ввода было скрыто, а фокус уходил в
невидимый элемент. Общий хелпер `showUrlStep()` теперь делает `show(demoIdle)`; он же
используется новой кнопкой.

### Про `scroll-margin-top`

В задании верно: на лендинге `scroll-margin-top` не было, и без JS якорь приземлялся под
липкую шапку (`landing.js` компенсировал это отступом 84px, но только с JS). Добавлено
общее правило:

```css
main[id], section[id], .demo-card[id], .doc-section[id] {
  scroll-margin-top: calc(var(--header-h) + 16px);
}
```

Работает и без JS, и на внутренних страницах, где `landing.js` не грузится. Прежнее
`.doc-section { scroll-margin-top: 24px }` убрано — 24px под шапкой 72px не спасали.

## 5. Побочная правка: наезд подписи на хром презентации

Кластер `.deck-theme` (язык + тема) и до правки перекрывал подпись `.deck-conf { right: 84px }`:
кластер шириной ~112.5px от правого края при `right: 26px`, подпись начинается на 84px —
**наезд 28.5px** (RU-подпись «Конфиденциально · Октябрь 2026» = 235.76px). Бургер увеличил
кластер до 136.5px, наезд стал бы 78.5px, поэтому подпись сдвинута:
`.deck-conf { right: 176px }` — зазор 13.5px. С `.deck-brand` (74.54px от левого края)
подпись не пересекается: её левый край теперь на 411.8px от правого края.

## 7. Чем проверено и что именно выполнилось

Браузера в песочнице нет, поэтому проверка трёх видов.

глифов читаются из настоящих `assets/fonts/*.woff2` через `fontTools` (переменные шрифты

и сжатие flex-элементов до `min-content`. Кросс-валидация: лого 95.84 / навигация RU
542.86 / CTA 465.88 против 99 / 545 / 469 в прежнем аудите; и главное — модель
воспроизводит замер из браузера (499px и 29px на вьюпорте 470). Перебраны вьюпорты
320…2400 с шагом 1px.

## 8. Нужно проверить в браузере

Расчёт и jsdom не заменяют рендеринг. Что посмотреть глазами:

**Переполнение**
1. `document.scrollWidth === innerWidth` на 360, 390, 414, **470**, 768, 1024, 1080, 1280,
   1440 — обе темы, RU и EN. Модель утверждает «да» везде; на 470 до правки было 499.
2. Ширина бургера на 360–600px равна 44px (не сплюснута), иконка по центру.
3. Порог 600px: на 600px кнопок в шапке нет, на 601px появилась primary — и ни там, ни там
   нет прокрутки. Проверить именно переход через порог.
4. Что является самым широким элементом страницы на 360px после правки шапки: модель
   считает только шапку, остальные секции не пересчитывались.

**Панель**
5. Панель закрывает страницу целиком: при открытом меню не видно hero-текста ни под
   панелью, ни между пунктами. Отдельно убедиться, что `backdrop-filter` на `.site-header`
   не обрезает и не размывает панель, нарисованную за пределами шапки, — это единственный
   пункт, который расчётом не проверяется в принципе.
6. Высота панели: `100dvh` в мобильном Chrome/Safari при показанной и скрытой адресной
   строке — нет ли пустой полосы снизу или обрезанных пунктов.
7. Панель на 360×640: по расчёту контент лендинга ~500px при доступных 568px — помещается
   без прокрутки; на доках длинный пункт «Финансовая модель и калькулятор» (331px с
   паддингами при 17px) переносится на две строки. Проверить, что перенос выглядит
   нормально и скролл панели работает.
8. Панель в тёмной теме (фон `--bg`, пункты `--ink`) — контраст, нет ли «грязи на грязи».
9. Скролл страницы при открытой панели: не прокручивается ли фон (проверял только

**Внутренние страницы и презентация**

## 9. Найдено попутно (не исправлял — вне рамок задачи)

1. **Шапка RU не помещается в сетку контейнера на десктопе.** Содержимое `.header-inner`
   на ≥1280px = **1152.59px**, а `.container` ограничен 1160px и даёт 1112px контента.
   Дефицит **40.59px** на любой ширине ≥1208px: правый край шапки уходит за сетку (на 1280 —
   41px до края экрана, на 1440 — 16.6px за границу контейнера). Горизонтальной прокрутки
   при этом **нет**: контейнер центрирован, справа остаётся запас (правый край 1236.59 при
   вьюпорте 1280). Комментарий в CSS утверждал «полный набор требует ~1225px», прежний
   аудит — «на ≥1280px всё помещается с запасом ≈95px»; по метрикам запаса нет, есть
   нехватка 40.59px. Комментарий исправил, вёрстку не трогал: правка означала бы сдвиг
   брейкпоинта 1280px и затрагивает всю шапку целиком. Решение за координатором.
   EN-версия в сетку помещается (999.31px из 1112px).
2. **Наезд `.deck-conf` на `.deck-theme`** — был до правки (28.5px), исправлен вынужденно,
   см. раздел 5.
3. **`#demo-change` оставлял пустую карточку** — исправлено, см. раздел 4.
