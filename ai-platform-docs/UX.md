# UX-спецификация и карта экранов

**Статус:** информационная архитектура MVP; визуальная система и интерактивные макеты TBD.

## 1. Принципы интерфейса

- Сначала ясность и доверие, затем декоративность. Не копировать конкретный продукт; добиваться уровня качества через консистентность, скорость, доступность и качественные состояния ошибок.
- Единые названия моделей и цены в лендинге, каталоге, API и usage.
- Показывать ограничения до выполнения запроса: доступность, поддерживаемые функции, лимиты и неопределённость стоимости.
- Каждый сложный экран имеет loading, empty, error, permission-denied и success state.
- Подтверждать разрушительные действия; после создания API-ключ показывать секрет только один раз.
- Адаптивность, клавиатурная навигация, видимый focus, контраст WCAG 2.2 AA как целевой ориентир.

## 2. Публичные страницы

### Лендинг `/`
- Hero: одно предложение о ценности, CTA «Начать» и «Документация».
- Как работает: один ключ → выбор модели → учёт использования.
- Каталог/сценарии — только фактически доступные модели; не использовать неподтверждённые логотипы/обещания.
- Для бизнеса: рублёвый расчёт/документы показывать только когда процесс реально доступен; CTA «Запросить подключение».
- Безопасность и данные: кратко, со ссылкой на подробную политику.
- Цены и ограничения, FAQ, статус сервиса, контакты, условия и конфиденциальность.
- Не публиковать ложные метрики, логотипы клиентов, сертификаты и гарантии.

### `/docs`
Quickstart, base URL, авторизация, примеры curl/SDK, каталог моделей, потоковая выдача, ошибки, лимиты, статус совместимости и changelog.

### `/status`
Доступность веб-приложения, API и моделей/адаптеров. Не раскрывать внутренние адреса и инфраструктурные подробности.

## 3. Аутентификация

- `/register`: email, пароль, подтверждение условий; ясная ошибка уже существующего аккаунта без лишней утечки сведений.
- `/verify-email`: подтверждение адреса и возможность запросить письмо повторно с rate limit.
- `/login`: email + пароль, показать/скрыть пароль, безопасная обработка ошибок, ссылка восстановления.
- `/forgot-password` и `/reset-password`: нейтральный ответ, одноразовый короткоживущий токен, отзыв прежних сессий по выбору/политике.
- `/invite/accept`: принять приглашение в организацию.
- PIN-клавиатура не является отдельным способом первичной аутентификации. Если позже нужна, она может быть только вторичным локальным unlock с ограничением попыток и после полноценного входа.

## 4. Кабинет пользователя / разработчика

Навигация: Обзор, Модели, Playground, Проекты, API-ключи, Использование, Биллинг, Документация, Настройки.

### `/app/overview` — обзор
Баланс/лимит и период (если включён учёт денег), запросы, ошибки, активные проекты, быстрые действия «Создать ключ» и «Тестовый запрос». Показать источник/период данных.

### `/app/models` — каталог
Таблица/карточки: публичный ID, провайдер (если его раскрытие согласовано), входная/выходная стоимость или отметка TBD, контекст/ограничения, streaming/tools, доступность, статус. Фильтры по возможностям. Сравнение не должно подразумевать одинаковое качество.

### `/app/playground` — тестовая консоль
Выбор модели, system/user messages, параметры, запрос/ответ, latency, токены/оценка и стоимость/оценка. Кнопка остановки для streaming. Секретные данные не показываются. Предупреждение, что запрос обрабатывается выбранной моделью и может быть сохранён согласно настройкам политики.

### `/app/projects` — проекты
Список проектов, участники/роль, лимит расхода, статус. Создание и архивирование с подтверждением. Персональные и организационные данные разделены.

### `/app/keys` — API-ключи
Создать с названием, проектом и лимитами; полное значение показывается однократно. Далее видны только префикс, дата создания/последнего использования и статус. Ротация и отзыв с подтверждением. Не передавать ключ в query string.

### `/app/usage` — использование
Фильтры периода, проекта, модели, состояния; таблица запросов. По умолчанию показывать метаданные, а не полный prompt/response. Статусы стоимости: окончательная, оценочная, ожидает сверки. Экспорт — только с проверкой прав и ограничением объёма.

### `/app/billing` — биллинг
Баланс/лимиты, тариф и период действия, начисления, счета/документы при наличии. Разделить потребление и денежное списание. Для неподключённых способов оплаты показывать честный статус и контакт, не имитировать автоматические платежи.

### `/app/settings` — профиль и безопасность
Имя, email, смена пароля, активные сессии, уведомления, удаление/деактивация аккаунта, ссылки на политики.

### `/app/org` — организация (для B2B)
Реквизиты, сотрудники, роли, приглашения, проекты, бюджеты и usage по подразделениям. Изменение реквизитов не должно задним числом менять выданные документы.

## 5. Административная панель

Доступ только по отдельной роли `platform_admin` с MFA (обязательность и способ TBD до запуска), ограничением сессий и аудитом. Не использовать общий админ-аккаунт.

- `/admin/overview`: здоровье API, очередь, локальные endpoints, ошибки, latency, usage/стоимость/маржа по доступному уровню агрегации.
- `/admin/tenants`: аккаунты, организации, статусы, лимиты и заметки; никакого просмотра паролей/секретов.
- `/admin/users`: поиск, блокировка/разблокировка, сброс сессий, приглашения; каждое действие с причиной.
- `/admin/models`: публичный каталог, адаптер, model ID upstream, capabilities, статус, версии/тарифы; staged change и rollback.
- `/admin/providers`: состояние адаптеров и credentials metadata (секреты только через секрет-хранилище, интерфейс секреты не раскрывает).
- `/admin/routing`: правила выбора и fallback; dry run, preview влияния и подтверждение изменения.
- `/admin/usage`: агрегаты по клиентам/моделям, сверка оценки и факта, экспорт с правами.
- `/admin/billing`: тарифные версии, корректировки, статусы документов/платежей; двойное подтверждение ручных корректировок.
- `/admin/incidents`: инцидент, затронутые сервисы/клиенты, таймлайн, статус и итог.
- `/admin/audit`: неизменяемый журнал действий, актор, время, объект, причина, correlation ID.
- `/admin/settings`: флаги, лимиты по умолчанию, политики хранения; критические настройки с подтверждением.

## 6. Будущий веб-чат (этап 2)

`/chat`: список диалогов, новый чат, выбор модели, потоковый ответ, stop/regenerate/copy, удаление диалога, индикатор лимита. Пустой экран объясняет доступные модели. Free quota отдельна от API-ключа, с антиабьюзом. Не использовать бесплатные квоты поставщиков, пока условия не разрешают такой сценарий.

## 7. Тексты и визуальный язык

Тон: русский, прямой, технически точный, без «магии» и без неоправданных обещаний. Термины вводить одинаково: «модель», «проект», «ключ API», «запрос», «оценочная стоимость». Ошибка объясняет причину и действие, но не раскрывает секреты/внутреннюю инфраструктуру.
